# RiceMix · Wokwi 线上仿真包

三个文件对应 Wokwi 项目的三个标签页：

| 文件 | 粘到 Wokwi 哪里 |
| --- | --- |
| `diagram.json` | 编辑器的 **diagram.json** 标签（整个文件替换） |
| `sketch.ino` | **sketch.ino** 标签（整个文件替换） |
| `libraries.txt` | 项目根目录新建，或书签栏的 **Library Manager** 里手填 `HX711` |

最快路径：打开 <https://wokwi.com/projects/new/arduino-uno>，把三个文件内容分别贴进对应标签，点绿色 ▶。

---

## 一、这个仿真能证明什么，不能证明什么

**能证明**：每 200 ms 采一次重量、什么时候该开泵、什么时候该提前断流、什么时候该补泵、超时/溢流/干转三条保险会不会触发。也就是**固件的决策序列**。

**不能证明**：泵真实流量、HX711 真实零漂与标定、称重噪声、泵启动把 5V 拉塌导致复位。Wokwi 没有水路模型 —— 泵开多久，秤上的数字**不会自己变**，那是真实世界才有的因果。

所以这里的跑法是：**人扮演物理**。你手动改秤上重量，看固件的反应对不对。

---

## 二、继电器为什么要写 `"transistor": "pnp"`

Wokwi 的继电器默认是 `npn`，它的逻辑是：

| `transistor` | IN = LOW | IN = HIGH |
| --- | --- | --- |
| `npn`（默认） | COM–**NO** 通 | COM–NC 通 |
| `pnp` | COM–NC 通 | COM–**NO** 通 |

而 `sketch.ino` 里出厂参数是 `trigLevel = 1`（HIGH 触发），泵接在 **NO**。两者要对上，`diagram.json` 里必须写 `pnp`。

**实物接线时看模块上的丝印**：市面上多数单路模块是**低电平触发**（IN 拉低才吸合）。如果买到那种，接好后在串口敲：

```
SET TRIG 0
SAVE
```

否则会出现「没到量泵一直转 / 一到量泵反而开」的反相故障。这一条在通电前必须确认。

## 三、第一次跑：四步

**第 1 步 · 空秤标定**（HX711 那块的滑块拉到 0）

```
ZERO
```

**第 2 步 · 放 1 kg 上去**

Wokwi 的 HX711 元件上方有个 `load` 控件（automation 控件，单位 **kg**），把它设成 `1`。此时原始读数是 420 counts（5kg 量程 = 0–2100 counts）。然后：

```
CAL 1000
```

会自动算出 `calFactor = 0.42`。这个数不是巧合：`2100 / 5000 g = 0.42 counts/g`。实物上因为传感器灵敏度不同，这个值通常在 200–450 之间，**必须用真砝码现场标，不能抄**。

**第 3 步 · 把秤清空，配重含义改成你要的**

想让「秤上 100 g 配重 = 代表 150 g 米」：

```
SET PORTION 100 150
SAVE
STATUS
```

**第 4 步 · 投米开跑**

```
MANUAL 120
```

固件会算出目标水 = `120 × 1.20 = 144 g`，然后拉高 D8 → 继电器吸合 → **PUMP 红灯亮**（这就是泵在转）。

现在你来当水路：看到红灯亮，就把 `load` 一点点往上加。加到接近 144 g 时，红灯应该**提前灭掉**（提前量 = `flowEst × (leadMs + 200) / 1000 ≈ 4.8 g`，默认参数下在 139 g 左右断流）。串口会打印：

```
== 完成：加水 143.7 g / 目标 144.0 g，误差 -0.3 g
== 耗时 11800 ms，补泵 0 次
```

## 四、串口命令速查（全都在 `sketch.ino` 里实现）

| 命令 | 作用 |
| --- | --- |
| `RUN` / `STOP` | 开始一轮 / 急停 |
| `STATUS` | 当前重量、状态、配置、误差 |
| `ZERO` | 软件去皮 |
| `MANUAL <米g>` | 手工指定这一轮的米量并开跑 |
| `SET PORTION <配重g> <代表米g>` | **改配重含义**（本项目的核心诉求） |
| `SET RATIO 1.35` | 改水米比 |
| `SET TIMEOUT 15000` | 改注水超时 |
| `SET LEAD 300` | 改提前断流补偿 |
| `SET TRIG 0` | 继电器反相（低电平触发模块用） |
| `CAL <已知g>` | 用已知重物标定 |
| `SAVE` / `LOAD` / `RESETCFG` | 存 EEPROM / 读回 / 恢复出厂 |
| `SIM <g>` / `SIMOFF` | 跳过 HX711，直接注入重量（纯逻辑调试用） |

`SIM` 模式在 Wokwi 里特别好用：不接秤、不管 load 控件，直接

```
SIM 120
MANUAL 120
```

然后自己用 `SIM 200`、`SIM 263` 一步步往上抬，看固件在哪个点停手。

## 五、故意搞坏它，看三条保险

| 玩法 | 怎么造 | 预期 |
| --- | --- | --- |
| 泵卡死 / 管路堵 | 拉高 D8 后一直不动 `load` | 20 s 后 `TIMEOUT`，泵强制关，进 FAULT |
| 溢流 | 把 `load` 猛拉到 4000 以上 | `OVERFLOW`，立刻关泵 |
| 干转 | 不让负载变，撑过 3 s | `DRY-RUN`，关泵 |
| 传感器坏了 | 数字纹丝不动 | 同上，最终 TIMEOUT |
| 断流提前量太保守 | `SET LEAD 800` | 断得早，SETTLE 后自动补泵 1–3 次 |

补泵上限是 3 次（`MAX_TOPUPS`），超过就认账收工，不会无限来回抽。

## 六、仿真里看不到、但实物一定会遇到的

- **泵启动瞬间的电压塌陷**：12V 泵启动电流能到额定的 3 倍，会把 5V 轨拉低，Arduino 直接复位。这就是方案里坚持「12V 独立供电 + 1000 µF 电容 + 共地」的原因，不是可选项。
- **余流**：泵断电后管路里的水还会继续滴 1–5 g。`leadMs` 就是给这个留的余量，实物上要实测（断电后立刻看秤，30 秒内还在涨多少）。
- **机械滞后**：水打到米面上，秤要 100–400 ms 才反映出来。所以 SETTLE 要等 `leadMs + 400 ms` 才复核，等太短会误判成「不够」而补泵。
- **挂壁**：水挂在容器壁上不会立刻落到秤上，误差 ±0.5 g 级别，属于正常的物理噪声。
- **HX711 零漂**：温漂会让零点慢慢走，所以每一轮结束都 `tare()`。

## 七、和实物接线的对应关系

| 仿真元件 | 实物 |
| --- | --- |
| `scale` (wokwi-hx711) | HX711 模块 + 5 kg 悬臂梁（四线：E+/E-/A-/A+ 已在元件内部接好，仿真里不可交互） |
| `relay` | 单路 5V 光耦继电器模块 |
| `pumpLed` + `r1` | 12V 直流水泵（仿真里用 LED 代替，因为它只反映「通电与否」） |
| `statLed` + `r2` | 板载 D13 状态灯 |

真实接线里 `relay:COM` 接的是 **12V+**，`relay:NO` 接泵正极，泵负极回 12V−，并且 **12V− 必须和 Arduino GND 接在一起**。仿真里因为用 5V 供 LED，COM 接的是 UNO 的 5V —— 这是仿真对现实的简化，别忘了实物是 12V 独立回路。

## 4×4 矩阵键盘（diagram.json 已内置）

仿真里挂了一块 `wokwi-membrane-keypad`，引脚与实物一致：

| Wokwi 引脚 | 接 UNO | 实物排线 |
|---|---|---|
| R1 R2 R3 R4 | D2 D3 D4 D5 | 键盘第 1–4 根（行） |
| C1 C2 C3 C4 | D6 D7 D9 D10 | 键盘第 5–8 根（列） |

D8（泵）和 D13（LED）被跳过，所以第 2 行第 3 列的 9 号脚不能给键盘用。

**在仿真里怎么试**：

1. 点键盘上的键，松手就是一次按下 → 串口会打印 `[KEY] 5 稠粥 1:6.0` 之类
2. 按第 1 行的四个键切配方，串口会打印新的 ratio / timeout / maxTotal 三元组
3. 按「启动」（第 3 行第 1 列）开始配比，先 `MANUAL 120` 或用 automation 面板拖 `load`
4. 长按第 1 行第 3、4 列（自定义 A / B）= 把当前参数写进该档

**Wokwi 的键盘是点按式**，没有真正的长按 —— 想验长按就把 `pollKeyHold()` 的 800 ms 临时改成 200 ms，或者直接用串口 `SAVE`。

**接反不烧**：行列互换只会让按键错位，发现按 A 键出 B 档，把 R/C 两组对调即可。
