# RiceMix on Arduino UNO — 全硬件控制版

ESP32 那块烧了，改回 UNO R3。**没有 WiFi、没有网页、没有 App**，全部靠键盘和 LCD 操作。

---

## 一、这套东西的引脚账

UNO R3 一共 20 个 IO，D0/D1 被 USB 串口占着，实际能用 18 个。这套东西要 13 个，**还剩 5 个富余**。

| 用途 | 引脚 | 数量 |
|---|---|---|
| **LCD1602 I2C（VCC/GND/SDA/SCL）** | **A4 = SDA，A5 = SCL** | 2 |
| 4×4 键盘行 R1–R4 | **D2 – D5** | 4 |
| 4×4 键盘列 C1–C4 | **D6 – D9** | 4 |
| **测重串口 RX** | **D10** | 1 |
| **泵驱动 IA / IB** | **D11 / D12** | 2 |
| 水位传感器 | **A0** | 1 |
| 备用 | A1 / A2 / A3 / D13 | 4 |
| **合计** | | **14** |

**A4/A5 被 LCD 占死**：UNO 的 SDA 就是 A4、SCL 就是 A5，这是硬件固定的，改不了。所以 LCD 一走 I2C，那两个脚就不能再给别的东西用——水位只能挪到 A0。

---

## 二、接线

### LCD1602 · I2C 四线（板载 PCF8574）

你手上这块 LCD 背面焊了转接板，只引出四个脚：

| LCD 转接板 | UNO | 说明 |
|---|---|---|
| VCC | **5V** | 转接板要 5V，不能接 3.3V |
| GND | **GND** | |
| SDA | **A4** | UNO 的 SDA 硬件固定是 A4 |
| SCL | **A5** | UNO 的 SCL 硬件固定是 A5 |

**就这四根。** 不用接 RS/EN/D4–D7，那些在转接板上已经转到 PCF8574 里去了。

**A4/A5 是死的**：UNO 的 I2C 不像 ESP32 那样能重映射，所以这两个脚一旦给了 LCD，就干不了别的。水位传感器只能挪到 A0。

**I2C 地址**：转接板背面 A0/A1/A2 三个焊盘全短接时是 `0x27`；如果全断开是 `0x3F`。固件里写死 `0x27`，不亮就改成 `0x3F` 再烧一次。

**驱动是自己写的**，只用 `Wire`，不依赖 `LiquidCrystal_I2C` 那个第三方库——因为 Arduino 自带的库目录里根本没有它，硬写 `#include` 会编译失败。

**背光**：转接板上有个跳线帽或者一个小电阻控制背光，默认是亮的。太亮就拔掉跳线帽。
### 4×4 键盘

| 键盘 | UNO | |
|---|---|---|
| R1 | **D2** | 第一行 S1 S2 S3 S4 |
| R2 | **D3** | 第二行 S5 S6 S7 S8 |
| R3 | **D4** | 第三行 S9 S10 S11 S12 |
| R4 | **D5** | 第四行 S13 S14 S15 S16 |
| C1 | **D6** | 第一列 |
| C2 | **D7** | |
| C3 | **D8** | |
| C4 | **D9** | |

**矩阵键盘不用上拉电阻**，代码里配 `INPUT_PULLUP` 就行。

### 测重 · WX112 V1.0

| 秤 4pin | UNO | |
|---|---|---|
| VCC | 5V | 这块是 5V 供电的 |
| TX | **D10** | 交叉：秤发，我们收 |
| RX | 不接 | 我们不需要给它发东西 |
| G | GND | |

**电平和 UNO 一样是 5V，不用分压、不用电平转换**——这是 UNO 比 ESP32（3.3V）省事的地方。

协议按厂商说明书：**9600 / 8N1，帧格式 `<数字>\r\n`，`0123\r\n` = 123 克**，只在称重界面发送。

### 泵 · 5V + L9110S

| L9110S | 接到 |
|---|---|
| VCC | 5V |
| GND | GND |
| **IA** | **D11** |
| **IB** | **D12** |
| OA | 泵**黑**线 |
| OB | 泵**红**线 |

**这批货的线是反的**：商家把泵的红线接到 OB、黑线接到 OA 了，而且那个接头带防呆方向，插不反过来，也只有这一根细线，改不了。

所以 IB 不能像原计划那样接地，**必须也接一根 GPIO（D12）**，在软件里把逻辑掰回来：

| IA (D11) | IB (D12) | OA | OB | 泵实际 |
|---|---|---|---|---|
| 0 | 1 | 低 | 高 | **正转，加水** |
| 1 | 0 | 高 | 低 | 反转，冲管 |
| 0 | 0 | 低 | 低 | 自然停转 |

**不要去改那个接头**。带方向的防呆头，硬掰会断针。软件两行就能解决。

**5V 泵直接从 UNO 的 5V 取电会烧稳压器**（USB 只给 500mA，泵启动瞬间能到 1A）。正确做法：**泵电源单独走一个 5V/2A 适配器**，只把 GND 和 UNO 共起来。

### 水位传感器（可选）

| 水位 | UNO |
|---|---|
| VCC | 5V |
| GND | GND |
| OUT | **A0** |

不装也能跑，固件里 `#define USE_WATER 0` 关掉即可。

## 三、按键怎么用

8 档配方直接印在键盘上，**按一个键就是选一档**：

| 键 | 配方 | 比例 | 超时 |
|---|---|---|---|
| S1 | 东北米 | 1:1.2 | 60 s |
| S2 | 泰国米 | 1:1.1 | 60 s |
| S3 | 软饭 | 1:2.0 | 90 s |
| S4 | 烂饭 | 1:3.0 | 120 s |
| S5 | 稠粥 | 1:6.0 | 150 s |
| S6 | 稀饭 | 1:9.0 | 180 s |
| S9 | **去皮** | — | — |
| S10 | **开始** | — | — |
| S11 | **急停** | — | — |
| S12 | **换页** | — | — |

**S7/S8/S13–S16 留空**，接成「自定义比例」以后再说。

**操作流程**：空碗放秤上 → S9 去皮 → 倒米 → 按键选配方 → S10 开始 → 等它自己停。

## 四、LCD 显示什么

秤自己带四位数码管显示克数，LCD 不重复，只报系统状态。四页，S12 翻：

| 页 | 第一行 | 第二行 |
|---|---|---|
| 1 进度 | `FILL ####...... 45%` | `54.0 / 144.0 g` |
| 2 状态 | `RATIO 1:1.20` | `FLOW 12.0 g/s` |
| 3 上次 | `#3 RICE 100 g` | `WATER 120 g  10s` |
| 4 故障 | `FAULT  no flow` | `check pump/tube` |

## 五、四道保险

和 ESP32 版一样，一道都不少：

| 保险 | 触发条件 | 表现 |
|---|---|---|
| 超时 | 超过配方的 `timeoutMs` | `FAULT timeout` |
| 超重 | 总量超过 3000 g | `FAULT overload` |
| 没出水 | 开泵 3 秒重量涨不到 0.5 g | `FAULT no flow` |
| 超量 | 超过目标 6 g | `FAULT overshoot` |

**「没出水」这条最有用**——泵卡死、进水管脱了、桶里没水，读数表现都是「重量不涨」，只有这条能抓住。

## 六、烧录

1. 装了 `LiquidCrystal`（Arduino 自带，不用装）、`Keypad` 可选（本固件自己扫，不依赖）
2. 板子选 **Arduino Uno**，端口选对
3. 编译上传，**先别接泵电源**，看 LCD 有没有背光和第一页
4. 按 S4 翻四页，四页都能显示 → 键盘 8 根线全通
5. 秤上放东西，LCD 第二页的 `FLOW` 或串口监视器应该能看到数字变化
6. 接上泵电源，放 50 g 米按 S10

**第 5 步没动静先看秤的数码管**——它只在称重界面发串口，按了菜单键或者跳进标定就静默，不是线的问题。

## 七、和 ESP32 版差在哪

| | ESP32 版 | UNO 版（现在） |
|---|---|---|
| 主控 | ESP32（3.3V） | UNO R3（5V） |
| 网络 | WiFi + MQTT + 网页 App | **完全没有** |
| LCD | I2C（现成库） | **I2C（自写驱动）** |
| 泵 | 12V + L298N | **5V + L9110S** |
| 秤电平 | 3.3V，要分压 | **5V，直连** |
| 键盘脚 | 8 个普通 GPIO | **4 个数字 + 4 个模拟** |
| 适用场景 | 能连网、能远程 | **插上电就能用，最稳** |

UNO 版**没有网络，但也因此没有网络故障**——校园网 SSO、AP 兜底、MQTT 掉线这些问题一个都不存在。这是它比 ESP32 版强的地方。
