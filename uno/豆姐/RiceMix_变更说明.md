# RiceMix UNO 固件变更说明（原始版 → v3.2）

## 一、最终键位（4×4 键盘，只用前两行 + 两个备用键）

| 键 | 功能 | 引脚列 |
|---|---|---|
| **S1** | 锁定 / 解锁米重（故障态下 = 清故障） | C1 = D6 ✅ |
| **S2** | 开始自动加水 | C2 = D7 ⚠️ 断线 |
| **S3** | 急停，任何时候有效，优先级最高 | C3 = D8 ✅ |
| **S4** | 翻页：主页面 ↔ 上一批记录 | C4 = D9 ✅ |
| **S5** | 目标水量 **+5g** | C1 = D6 ✅ |
| **S6** | 目标水量 **−5g** | C2 = D7 ⚠️ 断线 |
| **S7** | 手动开泵（排空气 / 冲管） | C3 = D8 ✅ |
| **S8** | 手动关泵 | C4 = D9 ✅ |
| **S9**（备用）| = S2 启动（S1 正下方） | C1 = D6 ✅ |
| **S13**（备用）| = S6 −5g（S5 正下方） | C1 = D6 ✅ |

> 默认水米比 **1:1.2**，S5/S6 在这个基础上 ±5g 微调（±200g 封顶），掉电复位。

## 二、改了什么，为什么这么改

### 1. 移除水位传感器（A0 空出）
- **改了什么**：删掉 `PIN_WATER` / `USE_WATER` / `waterMM()` 以及启动、加水过程中的两处水位检查。A0 归入备用脚。
- **为什么**：实际没装，留着代码只会误报 `tank empty`。而且「开泵 3 秒重量涨不到 0.5g」的 `no flow` 检查已经能同时抓住泵卡死、进水管脱落、桶里没水三种情况，比水位探头更管用。

### 2. 泵只在方向变化时写引脚
- **改了什么**：新增 `pumpSet(dir)` 统一入口，用 `pumpDir`（1 正转 / 0 停 / −1 反转）记录当前方向，方向没变直接 return，不碰 D11/D12。`pumpOn / pumpOff / pumpReverse` 全部走它。`pumpDir` 初值设成不可能的 −127，保证 setup 里第一次 `pumpOff()` 一定真写一次。串口手动试泵的 `l/h`（双低/双高测试）直接写脚后把 `pumpDir` 标脏，下次自动重同步。
- **为什么**：原代码 `pumpOff()` 在故障、停泵、急停、超时等多处重复调用，每次都拉引脚；叠加 I2C 卡顿或串口中断时可能把泵抖成脉冲。状态机屏蔽后，泵只在「真要换向」时动一次。同时双高刹车的停泵方式保留——bootloader 的 1~2 秒里引脚浮空会被干扰成高电平，双高下浮空 = 刹车，泵不动；双低下浮空 = 空转，不安全。

### 3. 接线表捋顺
- **改了什么**：头部注释按「固定占用（D0/D1/A4/A5）→ 键盘 8 连号 → 测重 → 泵 → 备用」重排，每根线标清接什么。占用合计 13 个 IO，富余 A0–A3 + D13 共 5 个。
- **为什么**：原表引脚和功能混排，接线时容易看错。分组连号后照着插即可。

### 4. S9 去皮 → S1 锁定 / 解锁，并显示预期水量
- **改了什么**：秤自带去皮，固件不再去皮。S1 按一下锁定当前米重（`RICE 120g LOCK`），主页面第二行直接显示 `WATER 144g +5`（= 米重 × 1.2 + 偏移，调偏移实时重算）；再按一下解锁。没锁定时提示 `S1 lock S2 go`。启动时已锁定就用锁定值，没锁定兜底抓当前读数。
- **为什么**：碗重由秤自己扣掉，固件再去皮是重复劳动。锁定后显示预期水量，用户在按启动前就能确认"这碗米要加多少水"，换偏移量也能立刻看到效果。

### 5. 删除 8 档配方，默认 1:1.2，S5/S6 ±5g
- **改了什么**：删掉 `RECIPES[8]` 数组、`recipeIdx`、调整页。`RATIO = 1.20f` 写死，`waterOffset` 记录 ±5g 偏移。`targetWater = riceWeight × 1.2 + waterOffset`。S12 翻页调整功能随之取消（S4 接管翻页，只剩主页面 / 上一批两页）。
- **为什么**：用户明确要求移除 S1–S8 的配方选择。实际使用中 8 档配方很少切换，1:1.2 加 ±5g 微调覆盖了"软一点/硬一点"的需求，操作从"选配方"简化成"锁米 → 微调 → 启动"三步。

### 6. 电子秤读不进的修复（重点）
- **改了什么**：
  - 解析器从「只收 0–9，等 `\r\n` 才解析」改成「整行缓存，跳到第一个数字/负号/小数点后 `atof` 解析」，兼容 `123.45g`、`+0012.3 g`、`ST,GS,...` 等带杂字符的帧。
  - 加**超时刷行**：200ms 没收到新字节就把当前缓冲当一行解析，无结束符的连续输出秤也能读。
  - 加**丢秤看门狗**：5 秒没解析到有效数据，LCD 显示 `NO SCALE / wire/mode/baud`，启动时拒绝并报 `no scale`。
  - 加**串口诊断**：每 2 秒打印 `[diag] bytes=… weight=… scaleLost=…`；按启动时打印 `[start] state=… scaleLost=… riceLocked=… riceWeight=… weightNow=…`，被闸门拦下时打印 `[start] ABORT: 具体原因`。`XW_RAW_DBG=1` 可把秤的原始字节以 HEX 打出。`XW_BAUD` 单独成宏，2400/4800/9600 挨个试。
- **为什么**：原解析器遇到带单位、小数点、逗号的帧直接解析错，且必须等 `\r\n`，很多秤连续输出不带结束符就永远读不到。看门狗和诊断输出把"读不进"从"静默用 0 克计算"变成显性报错，并能通过 `bytes=0`（硬件没通）vs `bytes>0 但 weight=0`（协议/波特率不对）一秒定位。SoftwareSerial 的 TX 占位脚从 255 改成真实存在的 A3(17)，避免某些核心上 255 号脚异常。

### 7. S2「锁定后按了没反应」修复
- **改了什么**：故障态下原来只有 S1 能清故障，S2 直接被忽略——而且故障态按 S1 是"清故障"不是"锁定"，用户很容易以为锁了其实没锁。现在故障态下 S2/S9 会先清故障再直接启动；`startBatch` 每道闸门都打串口。
- **为什么**：之前 `no scale` 故障锁存后，按 S2 被吞掉，看起来就是"没反应"。改成 S2 自带清故障重试后，锁存故障不再死锁。诊断打印则让"没反应"变成"看一眼串口就知道卡在哪道闸门"。

### 8. D7 断线确诊 + 备用键
- **改了什么**：加备用键映射——S9（S1 正下方）= 启动，S13（S5 正下方）= −5g，原 S2/S6 保留。故障态下 S9 同样能清故障启动。
- **为什么**：S5（+5g）正常、S6（−5g）失灵，而两者只差一列（S5=C1/D6，S6=C2/D7），且 S2（启动）也在 C2/D7——S2 和 S6 同时失灵，**确诊是 D7 那根线松了/断了**（S10、S14 也在这一列，同样不能用）。重插 D7→键盘 C2 即可根治；备用键让设备在修好前就能用。

## 三、排查过程复盘（以后出问题照这个来）

1. **秤读不进**：开串口监视器 115200，看 `[diag] bytes=`。
   - `bytes=0` → 查硬件：秤 TX → D10（交叉）、共地、秤在称重界面（菜单/标定模式静默）、5V TTL 电平（RS232 要加 MAX232）。
   - `bytes>0 但 weight=0` → 改 `XW_BAUD`（2400/4800/9600），或 `XW_RAW_DBG=1` 看原始字节。
   - 终极手段：秤 TX 改接 D0（硬件串口），不会丢字节，但**烧录时必须拔掉 D0 的秤线**。
2. **某键失灵**：按同列相邻键。S2/S6 同时失灵 = C2(D7) 断线；S1/S5 同时失灵 = C1(D6)；以此类推。备用键都放在 C1 列（S9/S13），一列全断也能启动。
3. **启动没反应**：看串口 `[start] ABORT:`。`no scale` 查秤；`rice <20g` 重新锁定；`already filling` 按 S3 急停重来。

## 四、最终引脚账

| 用途 | 引脚 | 说明 |
|---|---|---|
| LCD I2C | A4(SDA) / A5(SCL) | UNO 硬件固定，不可改；地址 0x27（不行试 0x3F） |
| 键盘行 R1–R4 | D2 – D5 | R3/R4（S9–S16）只用了 S9、S13，其余空 |
| 键盘列 C1–C4 | D6 – D9 | **C2=D7 断线，S2/S6/S10/S14 失灵，待修** |
| 测重 RX | D10 | 接秤 TX，SoftwareSerial 9600 8N1 |
| 泵 IA / IB | D11 / D12 | L9110S；泵线接反，软件掰回（IA=0 IB=1 正转） |
| 备用 | A0 / A1 / A2 / A3 / D13 | 原水位传感器已移除，A0 空出 |
| 调试串口 | D0 / D1 | USB，115200，看 `[diag]` / `[start]` 输出 |

泵电源**单独走 5V/2A 适配器**，只把 GND 和 UNO 共起来——从 UNO 5V 取电会烧稳压器。

## 五、v4 新增：终端协议 + 网页控制台

**一句话**：UNO 的串口现在能听命令行，网页控制台通过 USB 串口直接管它。键盘一个键没动，脱机照样能跑。

### 5.1 为什么走串口而不是 WiFi

UNO 没有网络。ESP32 那版能开网页是因为芯片自带 WiFi，UNO 想联网得加 ESP-01 模块，多一层 AT 指令、多一路供电、多一堆失败点。

USB 线本来就插着（烧录、看串口），WebSerial 让浏览器直接接管这根线，**零安装、零改动、零额外硬件**。

### 5.2 固件改了什么

| 改动 | 原来 | 现在 |
|---|---|---|
| 水米比 | `const float RATIO = 1.20f` 写死，重烧才能改 | `float ratio`，终端 `r 1.35` 改，写 EEPROM 掉电不丢 |
| 串口 | 只输出 `[diag]` / `[pump]` 调试信息，收单字符试泵 | 加行协议，`\r`/`\n` 一条命令 |
| 状态上报 | 没有 | `reportState()` 每 500 ms 或状态变化时打一行 `STATE …` |
| 参数持久化 | 没有 | `cfgSave()` / `cfgLoad()`，EEPROM 地址 0 放 magic `0xA5` |
| 单字符试泵 | `pumpProbe()` | 合进 `serialPoll()`，`a`/`b`/`x`/`l`/`h` 保留 |

**键盘和终端共用同一套底层函数**（`lock`→锁定逻辑、`go`→`startBatch()`、`stop`→`latchFault()`、`pump`→`pumpSet()`），所以两边天然互斥，不会打架。

### 5.3 命令表（电脑 → UNO）

| 命令 | 作用 | 回什么 |
|---|---|---|
| `r?` / `status` | 查全部状态 | `OK ratio=1.20 offset=0 rice=0 locked=0 state=IDLE weight=0 flow=0 target=0 scale=1` |
| `r 1.35` | 设水米比（钳 0.50–10.0） | `OK ratio=1.35` |
| `off +5` / `off -5` | 水量偏移（同 S5/S6） | `OK offset=5.0` |
| `off 0` | 偏移清零 | `OK offset=0.0` |
| `lock` | 锁定当前米重（同 S1） | `OK rice=120.0 target=144.0` |
| `unlock` | 解锁 | `OK unlocked` |
| `go` | 开始配料（同 S2） | `[start] …` 然后进 FILL |
| `stop` | 急停（同 S3，任何状态生效） | `OK STOPPED` |
| `pump on` / `pump off` / `pump rev` | 手动泵 | `OK pump on` |
| `save` | 存 EEPROM | `OK saved` |
| `reset` | 恢复出厂 + 清 EEPROM | `OK reset` |

失败统一回 `ERR <原因>`，比如 `ERR range`（比例超范围）、`ERR unknown <命令>`。

### 5.4 主动上报（UNO → 电脑）

```
STATE FILL added=52.3 target=162.7 flow=11.8 weight=172.3
DONE batch=3 rice=120 water=162.5
FAULT no scale
```

- `STATE` 每 500 ms 一行，状态一变立刻补发一行
- `DONE` / `FAULT` 只在状态切换那一瞬发一次
- `[diag]` / `[start]` / `[pump]` / `[cfg]` 是调试输出，网页控制台直接忽略

### 5.5 网页控制台

**怎么开**：

1. 烧 `RiceMix_UNO.ino`（Arduino IDE 里正常烧）
2. **双击 `启动控制台.bat`** —— 会起一个本地服务器并自动打开浏览器
3. 点「连接串口」，选 `CH340` 或 `Arduino` 那个口
4. 拖滑块 → 点「写入比例」

**为什么必须双击 bat**：浏览器的 WebSerial 只在 `https://` 或 `http://localhost` 下能用，直接双击 `control.html`（`file://`）是打不开串口的。bat 里跑的就是一句 `python -m http.server 8000`。

**页面上有什么**：

| 区域 | 内容 |
|---|---|
| 顶部 | 连接状态灯 + 当前端口 |
| 读数 | 秤上重量大字（56 px）、进度条（已加 / 目标） |
| 四格 | 米重 · 流量 · 状态 · 偏移 |
| 水米比 | 滑块 0.50–10.00（步进 0.05）+ 写入按钮 + ±5 g |
| 主控 | 锁定 / 解锁 / 开始配料 / 急停 |
| 手动泵 | 开 / 关 / 反转冲管 |
| 日志 | 带时间戳，按类型上色（`OK` 绿、`ERR` 红、`STATE` 蓝、`DONE` 橙） |

### 5.6 脱机怎么办

**键盘完全不受影响**。比例只在终端能改，但改完存 EEPROM，下次上电自动读回来——不带电脑也能按上一次调好的比例跑。

S1 锁米 / S2 启动 / S3 急停 / S4 翻页 / S5 加 5 g / S6 减 5 g / S7 手动开泵 / S8 关泵，全部照旧。

### 5.7 水位传感器（只提示，不拦截）

接法：VCC→5V、GND→GND、OUT→A0。nalogRead(A0) 读 0–1023，水越高数值越大。

**固件只上报，不做任何判断**。STATE 行末尾带 	ank=186，status 命令回的 OK 行也带。这样设计是因为电阻式探头的读数受水质、探头氧化、接触面积影响很大，硬约束会误报 	ank empty 然后卡住。

真正的「水快没了」提示放在网页端：水位区有个阈值输入框（默认 250），低于它进度条变橙、文字变「⚠ 水快没了」。**改阈值不用重烧**，纯前端判断。

不装水位传感器也完全没问题——	ank=-1，网页那块整块隐藏，什么都不影响。

### 5.8 编译体积

`.text 8450 B`（32 KB 的 **26%**）、`.data 6 B`、`.bss 200 B`（2 KB 的 10%）。

加了 EEPROM、字符串比较、命令解析，比 v3.2 的 4030 B 翻了一倍，但离 32 KB 上限还远得很。
