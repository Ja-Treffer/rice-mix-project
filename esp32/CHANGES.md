# 改造清单 · 从浇花版到米水配比版

对照 `wifi(1).ino` 和 `ricemix_esp32.ino`。看完这份就知道：拔什么、改什么、线插哪。

---

## 一页看完

| | 内容 |
|---|---|
| **拔掉** | DHT11、光敏、土壤探头、蜂鸣器 |
| **换掉** | 称重从「土壤湿度」换成 XW112 串口称重 |
| **加上** | 4×4 键盘（可选）、本地网页、本地 App、四页状态显示 |
| **不动** | WiFi 库、MQTT 平台（巴法云）、LCD1602 I2C、回调函数骨架、水位计 |

一句话：**只留下水位计和 L298N，其余传感器全换掉；称重走 XW112 自带的串口。**

L298N 留着，不是因为它比继电器好，而是因为它的接线端子能把泵线拧死，不像散件那样一堆杜邦线吊着。顺带白捡一个能力：**它能把泵倒转**，做完一批可以反冲三秒把管子里的水推回桶里。

## 二、物理上拔什么

这些东西连同杜邦线一起拔掉，不用留位置：

| 器件 | 原来接 | 拔掉后那个脚干什么 |
|---|---|---|
| DHT11 温湿度 | GPIO4 | **给 XW112 的 TX**（交叉后我们当 RX） |
| 光敏模块 | GPIO35 | 空着 |
| 土壤湿度探头 | GPIO33 | **给键盘行 R2** |
| 有源蜂鸣器 | GPIO15 | 空着（15 是 strapping 脚，别乱用） |
| **L298N 双路电机驱动** | GPIO18 / GPIO19 | **保留不动** ✓（泵线拧在端子上，比散件整齐） |

L298N 的输出端直接拧泵线，这是它比「继电器 + 杜邦线」强的地方。调速用不上，ENA 保持跳线帽接 5V。

因为 18/19 又被 L298N 占回去了，键盘列从 `{13,14,18,19}` 改成 `{13,14,5,17}`。

GPIO4 后来给了 XW112 的 TX，所以 C4 挪到 17——它本来是 XW112 的 RX，现在用不上，正好空出来。

## 四、线接在哪

全部接**扩展板的母座**，不往 ESP32 上直接插。按扩展板丝印找 GPIO 编号。

### XW112 称重模块

| XW112 4pin | 插到 |
|---|---|
| VCC | 扩展板 `3V3` |
| TX | GPIO4（我们的 RX，**交叉**）|
| RX | GPIO16（我们的 TX）|
| G | 扩展板 `GND` |

官方说明书（`112.pdf`）确认：芯片 `STC8H1K28`，**串口 9600 8N1**，帧格式 `<数字>\r\n`，
`0123\r\n` = 123 克。**只在称重界面发送**，进菜单或标定时静默。

悬臂梁那四根（红E+/黑E−/白S−/绿S+）已经在秤板左上角白座里，不用动。

### L298N 双路驱动（保留）

| L298N | 接到 |
|---|---|
| IN1 | GPIO18（正转 = 加水） |
| IN2 | GPIO19（反转 = 冲管） |
| ENA | 跳线帽接 5V（不调速） |
| +12V | 12V 电源 + |
| GND | 12V 电源 − **和** 扩展板 GND |
| +5V | 不接（板载稳压，别拿它给 ESP32 供电） |
| OUT1 | 泵红线 |
| OUT2 | 泵黑线 |

泵线拧在 OUT1/OUT2 的接线端子上，不用杜邦线——这就是留着它的理由。

**多出来的能力**：IN1/IN2 反着给电就能倒转泵。做完一批按一下网页上的 `Flush line`
（或串口发 `flush`），泵反转 3 秒把管子里剩的水推回桶里，下次配比起点更干净。继电器做不到这个。

### 水位计（保留）

| 水位计 | 插到 |
|---|---|
| VCC | 扩展板 `3V3`（**不是 5V**，模拟输出 5V 会超出 ADC 量程） |
| GND | 扩展板 `GND` |
| OUT | GPIO34 |

### LCD1602 I2C

| LCD | 插到 |
|---|---|
| VCC | 扩展板 `5V` |
| GND | 扩展板 `GND` |
| SDA | GPIO21 |
| SCL | GPIO22 |

### 4×4 键盘

| 键盘针 | 插到 |
|---|---|
| R1 | GPIO32 |
| R2 | GPIO33 |
| R3 | GPIO26 |
| R4 | GPIO27 |
| C1 | GPIO14 |
| C2 | GPIO13 |
| C3 | GPIO5 |
| C4 | GPIO17 |

C1/C2 用 GPIO14 和 13，C3 用 GPIO5，三根都在左排，和 R1–R4 同侧。

C4 用 GPIO17——它原本是留给 XW112 的 RX，现在秤只发不收，那个脚就空出来了。

GPIO5 是 strapping 脚（上电瞬间决定启动模式），配成 `INPUT_PULLUP` 时上电是高电平，正好是正常启动需要的状态，所以安全。别改成 `OUTPUT`。

### 泵和电源

| 从 | 到 |
|---|---|
| 12V 电源 + | L298N +12V |
| L298N OUT1 | 泵红线 |
| L298N OUT2 | 泵黑线 |
| 12V 电源 − | L298N GND **和** 扩展板 GND |

最后那根是共地线。两套电源，一个地。没有它继电器指示灯乱闪，泵该停不停。

泵线是裸铜头——对折一次塞进杜邦线母头，公头插扩展板。胶带把线缆绑在泵体上，别让拉力压在接头上。

## 四·五、XW112 的串口怎么读

说明书（`112.pdf`）已经把话说明白了，不存在「协议不统一」这回事：

| 项目 | 值 |
|---|---|
| 波特率 | 9600 |
| 数据位 / 停止位 / 校验 | 8 / 1 / 无 |
| 帧格式 | `<数字>\r\n`，`0123\r\n` = 123 克 |
| 发送时机 | 只在称重界面；菜单、标定、测试模式静默 |
| 发送节奏 | 菜单 `ts`：0 = 变化时发（≤3 次/秒），>0 = 每 ts 秒（默认 0.5） |

固件里就是这几行：

```c
#define PIN_XW_RX  4     // 板子 TX → 这里（交叉）
#define PIN_XW_TX 16     // 板子 RX → 这里
#define XW_BAUD 9600
float XW_SCALE = 1.0f;   // 说明书说发的是克

void xwPoll() {
  while (Serial2.available()) {
    char c = Serial2.read();
    if (c == '\r' || c == '\n') {
      if (xwLen) { xwBuf[xwLen]=0; weightNow = atol(xwBuf) / XW_SCALE; xwLen=0; }
    } else if (c >= '0' && c <= '9') { xwBuf[xwLen++] = c; }
  }
}
```

**接反不会烧，但一个字节都收不到。** 板子 TX 必须接我们当 RX 用的那个脚。

**串口静默先看数码管。** 说明书原文：「仅在称重界面、无标定、无菜单、非测试模式时发送」。
按了菜单键或者它自己跳进标定，串口就是安静的——不是线的问题。

**读数小一千倍**说明这块表的 `dot` 菜单被设成了 kg。别改代码，放 100g 发 `cal 100`，
固件自己算 `XW_SCALE`。

## 五、烧录前必须改的三处

代码顶部，`USER CONFIGURATION` 那一节：

```c
const char* STA_SSID     = "YourPhoneHotspot";   // ← 1. 你的 2.4G 热点名
const char* STA_PASSWORD = "hotspotpassword";    // ← 2. 密码
const char* MQTT_UID  = "207a31bb9be70df6839f3a3ca7e1ddc3";  // ← 3. 你自己的巴法云私钥
```

**SSID 不能是 5G**。ESP32 只有 2.4G 射频，5G 的 SSID 它根本扫不到，会一直连不上然后切 AP。

学校那种 eduroam 填了也没用（802.1X 认证），直接用 AP 兜底。

## 六、不用动的

- **库文件**：WiFi、PubSubClient、LiquidCrystal_I2C 三个照旧装
- **MQTT 平台**：还是巴法云，还是 9501 端口，只是主题名从 `pump`/`auto` 改成 `mixcmd`/`mixdata`
- **LCD 地址**：还是 `0x27`
- **水位计那个脚**：还是 GPIO34
- **回调函数骨架**：`void callback(char* topic, byte* payload, unsigned int len)` 结构没变，只换了里面的判断内容
- **L298N 模块本身**：物理接线只把原来的 `IN-A` 叫成 `IN1`、`IN-B` 叫成 `IN2`，位置没动
- **整体流程**：`setup()` 里初始化外设 → `loop()` 里轮询，这个骨架没变

## 七、改完怎么验

按这个顺序，每一步失败都对应不同的问题：

1. **只插 USB，不接 12V**，烧进去，串口 115200 看输出
   应该看到 `=== RiceMix ESP32 ===` 和三行初始化信息
2. **看 LCD**：有没有背光，第一页是不是 `READY  put rice`
   没有背光 → 换地址试 `0x3F`；全黑一行没有 → 595 那种接线问题这里不存在，大概率是 I2C 线松了
3. **按 S4 翻四页**，四页都能显示 → 键盘 8 根线全通
   只有部分页能翻 → 对应那根行/列线没插好
4. **秤上放东西**，串口应该开始打印数字
   一个字节都没有 → 先看秤的数码管在不在称重界面，再对调 TX/RX
   有数字但小一千倍 → `dot` 菜单是 kg，发 `cal 100` 校正
5. **接 12V，泵先不接**，按 S2 量 L298N 的 OUT1 对 GND
   L298N 没有继电器吸合声，只能量电压：该从 0 跳到 12V
6. **接泵**，放 50 g 米按 S2，看它加到多少
   差 10 g 以上 → 调 `LEAD_G`

第 4 步如果没动静，先确认**秤的数码管停在重量界面**——它只在称重界面发串口，进菜单就静默。
然后再对调 TX/RX。详细排查见 `README.md` 第二节。
