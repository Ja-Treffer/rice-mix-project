称重 + 注水功能的模拟测试方案
测量米的重量并加入合适的水量
核心诉求：在不接触实物元件的前提下，尽可能先把逻辑测试通过，降低损坏学校出借组件的风险。
一、问题定位
1.1 原方案遇到的障碍
团队发现在常规在线 Arduino 模拟器中，无法同时满足两个功能：
功能      |  硬件实现                         |  常规模拟器的支持情况
**测重**  |  称重传感器（Load Cell）+ HX711 放大器  |  大多数模拟器**不支持**（Tinkercad 没有 HX711）
**注水**  |  水泵 + 继电器 / MOSFET 驱动         |  **没有"水泵"和"水流"这种物理模型**
1.2 关键结论（先说答案）
"测重"是可以完整模拟的 —— Wokwi 原生支持 HX711（含 5kg / 50kg / 应变片三种型号），而且能在运行时实时拖动控件改变重量。  "水流"本身无法模拟（这是物理量），但"什么时候开泵、开多久、什么时候停"这套控制逻辑可以完整验证 —— 而这恰恰是最容易写错、最值得先测的部分。
二、测重部分：Wokwi 原生支持 HX711
2.1 官方支持情况
依据 [Wokwi 官方 HX711 文档](https://mintlify.wiki/wokwi/wokwi-docs/parts/wokwi-hx711) 与 [Supported Hardware](https://mintlify.wiki/wokwi/wokwi-docs/supported-hardware)：
项目          |  官方说明
元件名         |  `HX711 Load Cell Amplifier`（HX711 称重放大器）
支持型号        |  `"type": "5kg"` \                                    |  `"50kg"` \  |  `"gauge"`（应变片）
引脚          |  `VCC`(5V)、`DT`(串行数据)、`SCK`(串行时钟)、`GND`
库支持         |  标准 **`HX711` Arduino 库**
**可实时调重量**  |  Automation control：**`load`（float）= 设置秤上的负载，单位 kg**
2.2 支持的 API（标准 HX711 库）
文档列出的可用函数：
begin()        初始化秤
set_scale()    设置比例系数（标定）
tare()         去皮（清零）
get_value()    读取 ADC 原始值（已减去 tare）
get_units()    读取换算后的重量（可传整数做多次平均）
power_down()   进入低功耗
power_up()     退出低功耗
2.3 官方代码示例
#include "HX711.h"
HX711 scale;
void setup() {
Serial.begin(9600);
Serial.println("Initializing the scale");
scale.begin(A1, A0);
}
void loop() {
Serial.println(scale.get_units(), 1);
delay(1000);
}
2.4 必须知道的限制（重要）
官方原文："This chip does not implement channel B or gain settings of 32/64/128."
含义：模拟器不支持通道 B，也不支持 32/64/128 倍增益设置。
原始读数范围：
型号               |  原始值范围
`"type":"5kg"`   |  **0 – 2100**
`"type":"50kg"`  |  **0 – 21000**
实践影响：如果你的代码用了 `set_gain(128)` 或通道 B，模拟器会不工作。 需要改回默认的通道 A / gain 128 路径（标准 HX711 库默认就是这个）。
三、注水部分：用"控制逻辑"替代"水流"
Wokwi 没有水泵模型，但水泵的本质是"一个被数字信号控制的开关" —— 所以可以分层替代：
真实元件            |  Wokwi 中的替代                        |  能验证什么
**继电器模块**       |  ✅ **`Relay Module`**（Wokwi 原生支持）  |  数字信号 -> 继电器吸合
**继电器 + 水泵**    |  继电器输出端接 **LED** 或 **直流电机**        |  泵"开/关"的时序逻辑
**MOSFET 驱动泵**  |  **LED + 电阻** 直接接数字脚               |  PWM 调速逻辑
泵的实际水流          |  ❌ **无法模拟**（物理量）                   |  只能实物实测
结论：注水部分能验证的是"什么时候开、开多久、什么时候停"这套控制逻辑。
四、建议方案：把"注水"改成"闭环称重控制"
4.1 现在的可能做法（开环）
称米重 -> 按公式算出需要多少水 -> 开泵 N 秒 -> 停
^
依赖"流量恒定"这个假设
问题：泵的流量受电压、水位、管阻影响，波动很大 —— 算出来的秒数几乎不可能准。而且一旦泵卡住不停，就淹了。
4.2 改成闭环（更稳、也更安全）
称米重 -> 算出目标水量 -> 开泵
|
循环：称总重 -> 到目标了吗？
|
到 -> 立刻关泵
为什么更好：
|  开环（按时间）  |  **闭环（按重量）**
依赖流量恒定  |  是（不可靠）   |  **否**
精度      |  差        |  **准**（直接测结果）
安全性     |  泵卡住就溢水   |  **到达目标自动停**
代码复杂度   |  低        |  略高（只是加个 if）
而且这个设计在 Wokwi 里能完整验证 —— 因为两种情况都只用到了 HX711 + 数字输出。
4.3 代码骨架
float targetWater = riceWeight * RATIO;      // 例如 1 : 1.2
float startWeight = scale.get_units();       // 加米后的总重
digitalWrite(PUMP_PIN, HIGH);                // 开泵
while (scale.get_units() - startWeight < targetWater) {
delay(200);                              // 循环测重
if (millis() - t0 > TIMEOUT_MS) {        // 超时保护
digitalWrite(PUMP_PIN, LOW);
Serial.println("TIMEOUT - pump stopped");
break;
}
}
digitalWrite(PUMP_PIN, LOW);                 // 关泵
注意那个 `TIMEOUT_MS` 超时保护 —— 这是防溢水的关键保险，而且在模拟器里就能测出来（把 load 一直保持不变，看它会不会超时停泵）。
五、模拟器测不到的东西（别过度乐观）
模拟通过不等于实物能用：
模拟不了        |  后果                             |  怎么补
泵的实际流量      |  闭环能自适应，但要知道"大概多久到目标"           |  实物实测一次
HX711 真实标定  |  模拟的 `load` 是手输的，真实传感器有零点漂移     |  实物做 `tare()` 标定
称重噪声 / 抖动   |  模拟读数很干净                        |  代码里加滑动平均滤波
电源压降        |  泵启动瞬间拉低电压 -> **Arduino 可能复位**  |  分开供电 + 大电容
机械安装应力      |  称重传感器装不好会读数漂                   |  实物调试
六、实物测试的安全流程（四步走）
第 1 步：纯模拟（零风险）
在 Wokwi 里验证：
-  HX711 读数 -> 计算目标水量 -> 控制泵开 / 关
-  用 load 控件手动改变重量，看程序反应
-  测边界情况：重量为 0？重量不增加？超时？
这一步能抓出绝大部分逻辑 bug。
第 2 步：只测 HX711（低风险）
不要接泵，只接 HX711 + 称重传感器：
1. 用万用表确认 Arduino 5V 输出正常
2. 接 HX711 的 VCC/GND（注意极性！）
3. 接 DT/SCK 到数字脚
4. 串口打印原始读数
5. 放已知重量的东西（比如一包 500g 米）-> 验证读数是否合理
6. 跑 tare() 去皮 -> 再校准 set_scale()
HX711 最容易被烧的原因：VCC/GND 接反、E+/E- 接到传感器时接错。 建议：接线前先拍照，接完先别通电，用万用表通断档核对一遍。
第 3 步：只测泵（中风险）
只接继电器 + 泵，不接 HX711：
1. 先只接继电器，听"咔哒"声 -> 确认控制信号正常
2. 继电器输出端先接 LED（不接泵）-> 验证开关逻辑
3. 再换接泵，用【限流电源】限制电流到额定值的 1.2 倍
4. 测泵的实际电流（万用表串联）
5. 测实际流量：让它抽 10 秒，量水量 -> 得到 mL/s
第 5 步得到的"实际流量"数据，正好可以回填到模拟里，让模拟更贴近真实。
第 4 步：合并 + 加保护
1. 泵和 Arduino 【分开供电】（或加 1000uF 电容缓冲）
2. 泵的电源线上串一个【保险丝】或自恢复保险丝
3. 代码里必须有【超时保护】
4. 第一次跑的时候，容器里【只放水不放米】，从少量开始
5. 全程有人盯着，手放在电源开关上
七、低风险替代方案
如果觉得称重环节风险太大，还有这些退路：
方案                 |  做法                                     |  优缺点
**A. 混合方案**（推荐考虑）  |  用**厨房秤人工称米**（不动电子元件），**Arduino 只管注水**  |  风险最低；少了"自动测重"这个亮点
**B. 水位传感器**       |  用 **HC-SR04 超声波**测水面高度推算水量             |  Wokwi 支持 HC-SR04；精度差、易受蒸汽影响
**C. 流量计**         |  用 **YF-S201 水流传感器**直接计量注水量             |  比称重更直接；Wokwi 不支持，且要买
**D. 称重 + 定时双保险**  |  闭环为主，同时设最大时间上限                         |  **推荐保留**（即上文代码里的 TIMEOUT）
方案 A 值得认真考虑：如果核心目标是"AI 辅助烹饪助手"这类教育应用，"自动测重"不是必要条件，反而能降低风险、提高完成度。
八、总结
原顾虑         |  结论
"模拟器不支持测重"  |  **不成立** —— Wokwi **原生支持 HX711**（5kg/50kg/gauge），还能**实时拖动 `load` 控件改重量**
"模拟器不支持注水"  |  **部分成立** —— 没有"泵"和"水流"模型，**但用 `Relay Module` + LED/电机就能验证控制逻辑**
"想先测试再上手"   |  **完全可行** —— 按四步走，每步都把风险控制住
最重要的一条建议：
把"注水"改成"闭环称重控制" —— 不依赖流量恒定、精度更高、而且天然防溢水。这个设计在 Wokwi 里能 100% 验证。
